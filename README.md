# 视频仓

用于管理原创视频的研究记录、脚本、素材清单、剪辑工程说明和验收记录。

## 工作流程

1. **发现参考作品**：优先研究最近 30 天的公开视频，不足时扩大到 90 天并注明；记录链接、作者、日期和可见的单条互动数据。
2. **实际观看并分析**：区分画面、声音和字幕的验证范围；观察事实与创作假设分开记录。
3. **选择原创题材**：结合受众、素材和成本拟定方案，不照搬参考作品。
4. **准备素材**：核实来源、许可、署名要求和费用，登记本地文件位置。
5. **制作内容**：编写文案与分镜，完成画面、配音、字幕和混音，保存可恢复的项目状态。
6. **检查成片**：检查画面、声音、字幕、节奏和实际播放效果；技术检查与人工审看分别记录。
7. **审核交付**：成片先审核，获得具体平台和账号授权后再发布。

高互动数据不能证明传播原因；没有真实发布数据时，成片称为“待验证样片”。

## 建议目录

```text
docs/                 工作说明与项目记录模板
projects/<项目名>/    brief.md、research.md、script.md、storyboard.csv、assets.csv、qa.md
src/                  经检查的制作代码与工具
```

目录按需要创建，参见 [项目记录模板](docs/项目记录模板.md)。

## 提交约定

- 提交原创脚本、代码、研究来源、授权记录和项目说明。
- 密钥仅由运行环境提供；禁止提交密钥、登录凭据、个人资料、浏览器数据或本机账号配置。
- 原始素材、录屏、音频和成片默认留在本机；仓库内只记录相对路径、摘要和必要校验值。
- `.gitignore` 只帮助排除未跟踪文件，不能撤回已提交的内容；提交前仍须检查暂存区。
- 使用付费服务、扩展账号权限、删除已有成果或公开发布前，先获得明确确认。
- 第三方素材遵循各自许可；本仓库未指定开源许可证，不代表其中内容可以自由转载。

本仓库目前用于初始化资料管理；已有本机项目和视频尚未迁入，具体工具的可用性以实际验证记录为准。
